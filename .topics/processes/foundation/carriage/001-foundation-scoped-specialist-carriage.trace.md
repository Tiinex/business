# Foundation Scoped Specialist Carriage

## Current Read

The Refactor Anchor now owns one reconciled multi-workspace integration frontier, while delegated specialist roles should receive only the Workspaces required to execute and verify their bounded scope. Each carried Workspace remains complete source; scoped carriage must not become partial/source-by-reference transport.

## Specialist Handoff Rule

- Main Refactor Anchor retains the complete current integration frontier and is responsible for reconciliation.
- A child Handoff carries its controlling Task/Handoff, exact full-source Workspaces needed for execution, and the authority/contract material actually required for grounding.
- Business, Docs, Site or other sibling Workspaces are not automatically included merely because Foundation historically used a fixed 3/3 carrier.
- A role must not mutate a carried sibling outside Allowed Scope; cross-boundary needs return as blockers/change proposals.
- Child returns are candidates relative to the exact source they received and are reconciled by Refactor Anchor before becoming current.
- Normal Anchor-to-Sigma delivery remains one canonical Handoff carrier and may carry the full current Turn-2 frontier when that is the delivery scope.

## Full-Source Meaning

`full-source` means complete source for every Workspace the carrier claims to carry. It does not mean every Tiinex repository belongs in every carrier.

## Recovery Boundary

The Refactor Anchor must remain able to recover the shared frontier it has accepted even while child lanes are active. Child-lane source is not current merely because a Handoff package exists.

## Interpretation Limits

This is a bounded Foundation/Turn-2 operating refinement. It does not change Tiinex artifact Parent semantics, Workspace semantics, Handoff package integrity, or product-level export contracts.

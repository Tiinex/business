## Evidence Material

- Material: three Sigma real-host recordings, one multi-Handoff Transport failure screenshot, one carrier-root screenshot, the exact product-generated two-route Handoff package, and bounded current Core/VS Code source reproductions.

### Primary path materially improved

- A fresh Outgoing can carry Business/Core/VS Code through Attach, endpoint Role closure, Pack and Transport to a real Handoff package.
- Role endpoint closure no longer reproduces the earlier `endpoint-role.reference-missing` blocker on the successful path.
- Updating stale Workspace artifacts allows the operator path to progress materially farther than the prior Sigma gate.
- This proves the central product path is no longer structurally blocked in the same way as the earlier gate, but does not establish Major closure.

### Carrier purity defect

- The exact generated carrier exposes `tiinex-recipient-v2.transport.json` at recipient-facing package root.
- Current Core declares this file as transport-owned compatibility/control state and explicitly states it is not semantic authority.
- Current Core also already contains an artifact-first clean-carrier Phase 2 implementation whose inspection contract requires stored compatibility JSON to be absent and derives receiver truth from visible semantic artifacts plus exact payload bytes.
- Normal manufacture nevertheless emits the JSON manifest in the current user-visible carrier surface.
- Required property: recipient-facing Handoff packages must not expose this implementation/version-specific JSON sidecar as part of the normal Tiinex carrier surface. Removal must be architectural: orient/validate/ground/transport projection must qualify from visible Tiinex artifacts and exact payload bytes, not from a hidden/recreated equivalent manifest.

### Multi-Handoff Transport blocker

- Sigma could not send a multi-Handoff package to Transport; VS Code reported that one or more Handoff routes could not produce valid carrier projection.
- The exact attached product carrier independently orients with two qualified routes.
- Anchor reproduced a shared projection failure: route-specific `project-handoff-carrier-output` remains blocked for both explicit routes instead of producing one valid selected-route human transport projection.
- Required property: a qualified multi-route carrier must expose each qualified route independently to Transport; one route must not be projected as pointerless/route-less solely because siblings exist, and one invalid route must fail visibly without corrupting other qualified route truth.

### Live Outgoing Workspace discovery remains over-broad

- Sigma's real Select Outgoing Workspaces surface includes acceptance/test Workspaces such as `extension-host-acceptance` / `001-3-acceptance` beyond the operator's actual selected/open Workspace roots.
- The prior Core top-level operator-context correction fixed one known nested Workspace leak, but the live Outgoing selector still reaches a broader discovery path.
- Required property: production Outgoing choices are bounded to explicit operator Workspace roots and qualified Workspace artifacts; nested repository fixtures/acceptance workspaces must not become live choices because of repository proximity.

### Stale Outgoing qualification lifecycle

- After Workspace artifact repair/reinitialization, an already-existing Outgoing retained stale source override state and Pack failed with `tiinex.package-builder.workspace-source-override-unqualified:extension-vscode`, while a newly created Outgoing could proceed.
- Required property: when a Workspace source identity/qualification changes, existing Outgoing state must either requalify against current exact source or become visibly invalid before Pack. Stale source overrides must not survive silently until late packing.

### Host lifecycle defects

- The same Handoff can be Attached more than once through the host path. Durable identity/path qualification must prevent duplicate semantic attachment rather than relying on display collapse.
- Tree state can fail to visibly refresh until a notification/toast is dismissed. Notification lifetime must not act as a state/refresh barrier.
- Role/material/cache lookup remains inconsistent enough in the replay to require a regression check, but no new semantic ownership is inferred from that observation alone.

## Required Recovery Properties

- Clean recipient-facing carrier with no `tiinex-recipient-v2.transport.json` or equivalent hidden compatibility authority.
- Single- and multi-Handoff route projection/Transport both qualified from exact carried route truth.
- Outgoing Workspace discovery bounded to explicit operator roots and qualified Workspace artifacts.
- Existing Outgoing contexts deterministically requalify/invalidate after Workspace source identity changes.
- Duplicate Attach rejected by exact durable Handoff identity.
- Tree refresh independent from toast/notification dismissal.
- Existing successful single-Handoff Attach -> Pack -> Transport behavior must remain green.
- No fix may delete/move fixtures merely to hide discovery leakage, infer semantic authority in VS Code, or turn transport/control representation into semantic truth.

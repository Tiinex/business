# Architecture Recovery Audit Before Further Host Mutation

## Objective

Stop further VS Code patch-loop mutation and re-establish the Tiinex semantic/tooling/host boundaries after Sigma observed architectural drift, opaque cache material, participant/packing regressions, and host-specific edge-case accumulation.

The work is an audit-and-disposition tranche. It must recover the lost end-of-session design frontier without treating video/chat recollection as canonical authority, independently inspect the current qualified Business/Docs/Core/VS Code state, and route any semantic, shared-mechanical, or host-only changes to their correct owner before implementation resumes.

## Done Criteria

- Axiom independently disposes the semantic contract questions around Handoff endpoint optionality, unresolved/ambiguous/contradictory endpoint material, durable Reference versus internal material binding, and the authority boundary for transparent carried material.
- Loom independently audits current Core material-closure/packing/reference mechanics and returns a minimal Core-owned correction/refactor plan without assuming the Anchor-recovered design is correct.
- Kodax independently audits Extension VS Code for duplicated shared mechanics, monolith/edge-case growth, participant/packing/incoming/attach failure seams, and returns a host-thinning plan without changing shared semantics.
- Each specialist distinguishes source-proven facts from inference and returns concrete contradictions or blockers rather than harmonizing with Anchor expectations.
- Anchor reconciles the independent returns before authorizing implementation; no specialist return alone becomes program acceptance.
- Sigma remains outside implementation and receives a new real-operator gate only after automated cross-layer acceptance demonstrates a coherent candidate.

## Dependencies

- Current Business Anchor/Axiom/Loom/Kodax canonical-holder Roles.
- Current canonical Docs Handoff and transport/material semantics.
- Current Core master source and qualification artifacts.
- Current Extension VS Code master source plus durable Sigma feedback/recovery artifacts.
- The incoming full-source recovery carrier remains the accepted latest-known recovery state; recovered video/chat observations are evidence for audit questions, not replacement authority.

## Scope

- Semantic contract audit for Handoff endpoint/reference/material-resolution boundaries.
- Core material closure, packing, participant projection, durable reference/internal binding, and fail-fast seams.
- Extension VS Code host/shared-mechanics boundary and controller-level acceptance coverage.
- Recovery-safe orchestration and independent specialist return manufacture.

## Exclusions

- No production implementation before specialist reconciliation.
- No release, publication, deployment, or remote mutation.
- No Sigma debugging/repair work.
- No broad repository cleanup unrelated to the discovered architecture boundary.
- No promotion of recovered chat/video text into canonical semantics without the owning Role/artifact disposition.

## Sequencing

1. Delegate semantic audit to Axiom, Core/mechanical audit to Loom, and host-boundary audit to Kodax using qualified Tiinex Handoffs.
2. Consume each return independently and preserve disagreements.
3. Reconcile into one Anchor disposition and bounded implementation sequence.
4. Delegate implementation only after ownership and acceptance boundaries are explicit.
5. Run machine-level cross-layer acceptance before returning a candidate to Sigma.

## Recovery Discipline

Maintain a qualified recovery carrier at every meaningful frontier change. Do not let chat/video reconstruction become the only copy of specialist results or reconciliation state.

# Successor Grounding Gap Review

## Purpose

Turn successor grounding friction into targeted durable improvement without inflating every Role or Handoff with repeated prose.

## Classification

Classify each real gap as one of:

- missing Role constraint
- missing authority boundary
- missing Process rule
- semantic ambiguity
- Tooling/allocation ambiguity
- undocumented operator convention
- excessive chat-history dependency

## Routing Rule

- Temporary misunderstanding: correct in the current Handoff when sufficient.
- Recurrent operational rule: improve Process.
- Role-specific responsibility: improve Role.
- Semantic ambiguity: route to canonical semantic authority.
- Tooling/allocation ambiguity: improve qualified Tooling/contract surface.
- Do not add prose everywhere merely because one model misunderstood something once.

## Lineage Separation

Semantic Parent, path/filename allocation, directory-local allocation context, carrier routing/progression, package version and conversation/UI branching remain separate concepts unless a qualified declaration explicitly relates them.

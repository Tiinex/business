# Extension Host End-To-End Acceptance Completion

## Objective

Close the only remaining pre-Sigma gap: prove the already-accepted VS Code host repair through a reproducible real VS Code Extension Host operator-flow gate under both exact Local Core and lock-qualified Published Core without widening product semantics or reopening general refactoring.

## Done Criteria

- Preserve the current Kodax host repair unless the real Extension Host gate exposes an exact defect. Do not reopen broad participant, packing, Transport, Incoming, or controller design work merely to make tests easier.
- The repository-owned acceptance harness must launch a true VS Code Extension Host in both `local` and `published` Core modes. A test that only parses source, imports helpers under Node, checks command registration, or executes refresh-only commands does not satisfy this criterion.
- The real host gate must drive the production controller/registered-command path far enough to prove one deterministic fixture through: Incoming carriage, Replace/landing into a disposable target, Outgoing construction, attachment of two qualified Handoff routes, visible Core-qualified participant presentation/confirmation, two-Handoff Pack, Core qualification of the produced carrier, exact Transport route/text projection, and restart/reload requalification before continued use.
- The real host gate must prove the participant boundary: a Core-qualified participant set is presented from Core truth, cannot be weakened into a partial host-owned set, and Pack reprojects or otherwise consumes the exact current Core-qualified set rather than persisted host semantic state.
- The real host gate must include negative cases at the owning operation: at minimum one invalid/unqualified Handoff that is rejected before late Pack, one pointerless Workspace carrier that remains free of synthetic Handoff `Continue from` text, and one restart case showing persisted host bookkeeping cannot substitute for Core requalification.
- The Local-mode run must use the exact Anchor-accepted Core source carried from the prior tranche. The Published-mode run must use the extension's lock-qualified published dependency and must not silently fall back to Local source.
- Test fixtures and deterministic interaction adapters may be added only at VS Code-owned presentation/controller seams and must exercise the same production controller path used by normal commands. They must not bypass the host by calling Core manufacture/participant helpers directly and then label that result Extension Host acceptance.
- The Extension Host runner must be reproducible from repository-owned test tooling or an explicitly qualified available host capability. If no runner/dependency can be obtained in the execution environment, return the exact blocker plus a runnable repository-owned gate; do not report candidate-for-Sigma.
- Obtain clean dependency-backed `typecheck`, relevant package/integration regression, and the exact Extension Host gate receipts when the environment supports them. Any environment limitation remains explicit and does not become PASS.
- Return exact source delta against the current accepted Kodax candidate, exact test receipts, residual risks, and one Kodax-to-Anchor Handoff with disposition `candidate-for-anchor-reconciliation` only if every required machine gate above actually passes; otherwise return `blocked` with the first exact blocker.

## Scope

Extension VS Code acceptance harness, deterministic host-test fixtures/adapters at legitimate VS Code-owned seams, and only the minimal product correction directly exposed by the real Extension Host gate.

## Dependencies

- Anchor Kodax Host Repair Acceptance And Machine Gate Disposition Decision.
- Exact current Kodax-returned Extension VS Code candidate source.
- Exact Anchor-accepted Core source for Local mode.
- Existing lock-qualified Published Core dependency for Published mode.
- Canonical Docs and Business authority remain read-only except bounded Evidence/return authoring.

## Boundaries

- No Core or Docs mutation.
- No Handoff/participant/cache/material semantic widening.
- No general `operatorTrees.ts` refactor unless an exact acceptance failure requires a bounded host-owned extraction to make the production path correct/testable.
- No replacement of real Extension Host execution with Node mocks, regex/source assertions, command-existence checks, package-only tests, or direct Core helper invocation.
- No Sigma involvement during debugging or machine-gate completion.
- No release, publication, deployment, push, or other remote mutation.
- If the gate reveals a shared Core/semantic capability defect rather than a host defect, stop and return it to Anchor instead of recreating shared logic in the extension.

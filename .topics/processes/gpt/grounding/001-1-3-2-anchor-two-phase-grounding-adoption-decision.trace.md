# Anchor Two-Phase Grounding Adoption

## Decision

- State: accepted
- Subject: operational startup behavior for the current `Anchor Role — Successor Evolution Continuation`
- Decision: adopt [Anchor Grounding — Stable Baseline Then Current Frontier](001-1-3-anchor-stable-baseline-then-current-frontier.trace.md) as the required operating startup instrument whenever a fresh session takes over Tiinex in Anchor capacity. The stable executive/organizational baseline is recovered first; the exact current carrier/Handoff is then grounded for transient work state. A fresh Anchor should not rely on Sigma to reteach qualified foundational Tiinex distinctions before it can operate.

## Basis

- The current Anchor Role already owns cold-start trust, successor recovery, recurring grounding-gap routing and replayable successor acceptance.
- Fresh-successor evidence shows materially correct bounded decisions with effectively zero Sigma correction turns across the stable decision matrix; remaining issues were primarily acceptance-harness isolation rather than foundational Anchor understanding.
- Sigma explicitly clarified that practical re-grounding speed is measured by the number of corrective information turns he must provide, not raw CLI wall-clock time.
- Executive Grounding and the Docs Anchor Successor Semantic Grounding Capsule deliberately separate stable meaning from transient recovery/lane status, making a two-phase startup the natural composition rather than embedding current state into Role prose.

## Consequences

- Future Anchor-to-Anchor takeover Handoffs should carry the current Anchor Role, Executive Grounding, Docs successor semantic capsule, this Decision/process, and the exact current recovery/Handoff frontier as Required Context.
- `grounded-to-act` for an operational takeover requires explicit holder binding where Tooling requires it plus sufficient stable baseline and current route/context.
- A package may supply the current route, but package placement does not become the stable project model and does not bind the holder by itself.
- If Sigma must correct a fresh Anchor on stable project/authority distinctions, the correction is evidence for the successor-grounding improvement loop and should be routed to the narrowest durable owner.
- New Sigma intent, preferences, observations and product/human acceptance remain normal human input and are not counted as grounding failure.
- This Decision is the operative adoption surface rather than rewriting or forking historical Anchor Role bytes whose current schema-reference authority is not cleanly continuable through ordinary authoring.

## Review Conditions

- Review when the Anchor Role receives a later qualified continuation that directly incorporates this startup responsibility, or when fresh production takeovers show repeated correction-turn friction that this process does not prevent.

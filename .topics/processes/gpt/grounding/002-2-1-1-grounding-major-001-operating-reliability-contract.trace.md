# Grounding Major 001 — Operating Reliability Contract

## Decision

- State: accepted
- Subject: operational composition of fresh/re-grounded Anchor behavior, recipient projection, specialist epistemic ownership and qualified return discipline
- Decision: the adopted stable-baseline/current-frontier grounding process and the accepted specialist epistemic/qualified-return decision are one operating sequence for Anchor-led work. Tooling may establish bounded route readiness first, but Anchor must not treat that projection as project-wide understanding; before mutation it must compose the stable qualified authority baseline, interpret the exact current route through that baseline, and preserve recipient, validation and transport boundaries without Sigma reteaching.

## Preferred Cold-Start Sequence

1. Enter through the carrier's exact Start/bootstrap contract. Before Tooling takeover, host behavior is limited to the declared bootstrap allowance; native package archaeology is not a substitute for Tiinex orientation.
2. Use the package-selected route through Tiinex Tooling and bind the consuming session to the qualified recipient Role explicitly when required. `grounded-to-act` means the selected bounded route is actionable; it does not mean the session has recovered the whole Tiinex program model.
3. Before treating the local frontier as project truth or performing Anchor mutation, compose the stable qualified baseline available in carriage: Tiinex organization/root identity, current Executive Grounding, current Anchor Role, the stable-baseline/current-frontier process and adoption decision, and the Sigma human-boundary. When the Docs-owned Anchor successor semantic capsule is carried, include it; when an external stable source is not carried, keep that limitation visible rather than inventing it.
4. Recover the current route, retained responsibilities, exact current Recovery/frontier, blockers and human gates proportionate to the authority actually transferred. A bounded lane must explicitly preserve any whole-program authority retained by Master Anchor rather than rebuilding or coordinating unrelated Majors.
5. Only then plan or mutate within the transferred scope. Stable doctrine does not absorb transient status, and current Handoff facts do not silently override stable authority.

## Re-Grounding Triggers

Reassess the relevant stable/current composition before further mutation after any of these material changes:

- qualified specialist return or material blocker;
- new Recovery/checkpoint or selected carrier;
- Major open, close, re-scope or reconciliation;
- source-frontier reconciliation or accepted-byte change;
- uncertainty about Role, holder, repository, semantic or human-gate authority;
- material context drift where chat memory and durable current state may differ;
- branch/fork continuation or runtime/session loss risk.

For branch/fork or material runtime fragility, prefer a fresh start from the newest qualified Recovery/carrier over extending a stale branched conversation. Re-grounding is not permission to broaden scope or infer missing provenance.

## Recipient Projection

When Sigma or another qualified human gate is the current recipient, default to scan-first decision surfaces:

- meaningful delta/state first;
- explicit blocker second when one exists;
- concrete next human action/gate third;
- deeper implementation history only when it changes the decision;
- exact copyable routing/transport text in a fenced block;
- Prefix/Major, Role and Workspace remain visibly distinct and are never used as aliases for one another.

Human observation, preference and acceptance remain separate from machine qualification. Concision must not hide uncertainty, failed gates, unaccepted source or missing authority.

## Specialist Epistemic And Transport Boundary

The accepted `Specialist Epistemic Ownership And Qualified Return Discipline` remains controlling for specialist work:

- implementation owners retain responsibility for available coarse workspace-health gates plus focused evidence;
- `implemented`, `validated`, `implementation-ready` and `human-accepted` remain distinct;
- inability to run a required gate is an explicit blocker, not a green return;
- Sigma is not the default debugger, source repairer, patch applier or integration-test team;
- normal completion transport is one qualified Tiinex Handoff package plus exact routing text; a loose patch or human-application request is a process failure, not a convenience path.

## Defect-To-Owner Routing

Route recurring defects to the narrowest qualified owner instead of accumulating Anchor-only warnings:

- Business / Anchor Process or Role: grounding order, re-ground triggers, Recovery hygiene, recipient projection, orchestration discipline;
- Docs / Axiom: canonical semantic contracts, schema/reference meaning, semantic authority;
- Core / Loom: shared host-neutral Tooling, qualification, projection, materialization or package mechanics;
- repository specialist: local implementation, build/compile/integration health and repository-specific harnesses;
- host/provider surface: provider-specific bootstrap/UI behavior that must remain non-authoritative.

This lane may create bounded routed work for a peer owner but does not implement across that authority boundary.

## Measurement And Replay

Track at minimum:

- Sigma correction turns needed to supply already-durable stable grounding/process knowledge;
- cases where Sigma is asked to debug, patch, repair source or discover ordinary build failure;
- qualified-return transport violations;
- whether a fresh successor recovers scan-first communication and the correct bounded program/authority context without parent-chat coaching.

New intent, preference, product judgment, genuine missing authority and explicit human acceptance are legitimate Sigma inputs and are not correction-turn failures.

A replay claim must distinguish machine ingress qualification from successor behavior. `qualify-cold-start` can qualify the preferred Tooling ingress and pre-takeover host path, but it does not by itself prove that an independent fresh successor cognitively recovered the operating contract. Behavioral closure therefore requires a genuinely fresh successor run from the qualified durable result with no answer coaching; until that run exists, report the behavioral gate as open rather than self-accepting it.

## Consequences For Handoffs And Recovery

- Anchor-to-Anchor handoffs claiming operational takeover should carry enough qualified stable-baseline material and exact current frontier to make the composition executable without Sigma briefing.
- Material accepted changes are followed by a stable committable Recovery/Handoff checkpoint so normal provider/session loss is bounded to the latest uncheckpointed iteration.
- A package/manufacture failure blocks normal return; it does not authorize loose-patch fallback.
- This Decision does not redefine `grounded-to-act`, add a canonical grounding state, create Sub-Anchor authority, or make current chat/provider behavior semantic truth.

## Review Conditions

Review this Decision when a later qualified Anchor Role continuation incorporates these responsibilities directly, when an independent fresh replay shows a recurring correction-turn class not covered here, or when Tiinex Tooling gains a qualified mechanism that changes the cold-start/replay evidence boundary.

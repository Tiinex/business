# VS Code Re-entry — Contract, Participant And Latency Closure Evidence

## Supported Claim Or Question

- Supported Claim Or Question: can the remaining Sigma-observed Handoff dropdown, routed pointer and 30–50 second host-latency failures be corrected in VS Code without inventing semantics or reopening Core?
- Evidence Role: exact root-cause, implementation and machine-qualification evidence before the next real Windows VS Code acceptance run.
- Supported Conclusion: yes at the machine-qualified boundary. The Handoff form was flattening Core group inputs, participant UI state was being treated as semantic authority after Core projection, and Outgoing repeatedly qualified the same selected Workspaces and repeated dry manufacture passes. VS Code now follows the exact Core creation shape, consumes only Core-qualified semantic participants for carrier manufacture, excludes already-carried Workspaces from discovery-only material, parallelizes independent read-only source/endpoint projection, avoids broad operator-context discovery when exact selected sources close the request, and removes redundant manufacture passes while preserving physical-carrier qualification. Core remains frozen.

## Provenance

- Known Source: Sigma's latest silent real-host video against Handoff 013, exact Business/Core/VS Code/App/Docs Workspaces, current Core Handoff creation/participant contracts, direct exact-Core authoring and package receipts, baseline/current latency probes, bridge regression and package-integration output.
- Preservation Basis: preserve Package V1, exact Core semantic ownership, carrier/artifact-lineage separation, physical pointer manufacture and the existing five-Workspace recovery frontier; change only demonstrated VS Code host mapping/orchestration and redundant execution.
- Provenance Limits: no final real Windows Extension Host/UI acceptance after these exact corrections is claimed. Host timings measured in the audit environment are comparative evidence, not a Windows performance guarantee.

## Evidence Material

- Material: latest Sigma real-host observations, current Core creation and participant projections, corrected VS Code source, exact five-Workspace benchmark probes, 121-case bridge regression and six-scenario package integration.
- Material Kind: VS Code correctness and operator-latency closure evidence.
- Dropdown root cause: Core projects Completion Expectation and Interpretation Limits as structured group inputs, but VS Code Handoff presets supplied their member fields as top-level values. The same host path also had to place endpoint References in whichever exact group container Core projects, notably Return To under Completion Expectation. This caused exact draft creation to fail despite qualified Role dropdown endpoints.
- Dropdown correction: VS Code presets now preserve Core's group structure and the endpoint helper writes semantic labels plus exact Markdown-Link References into the exact already-projected value container. Direct exact-Core reproduction creates a VS Code Handoff from Glimmer to Pilot with Business-qualified Role References in about 1.6 seconds and returns a ready draft.
- Participant root cause: the host exposed broad endpoint Role inventory as an additional-participant choice, then retained raw operator selections separately from Core's exact semantic participant projection. Downstream Files/Pack could therefore feed stale/raw selection state back into manufacture even after Core had projected a different exact participant set.
- Participant correction: the ordinary Outgoing path no longer derives semantic participant choices from Role/endpoint inventory. It asks Core for the exact current route participant projection with no inventory fallback, confirms that projection, and stores that exact Core-qualified Role set as the participant material supplied to Files/Pack. Routed manufacture still re-projects immediately before manufacture and replaces stale controller state with current Core output.
- Pointer closure: package integration requires physical Core-generated Handoff pointer and participant Role pointer files in the finished multi-route carrier and re-orients the result ready. Outgoing Files continues to index the exact temporary Core-manufactured carrier bytes, so pointer visibility is now downstream of the same physical carrier that Pack qualifies rather than a host-private pending tree.
- Qualification de-duplication: selected Outgoing Workspaces are excluded from discovery-only source overrides. Exact selected source roots bypass the older repository-wide operator-context scan when they already close the requested Workspace set. Independent Workspace, endpoint and route-source projections use bounded parallelism instead of serial one-process-per-root execution.
- Manufacture de-duplication: pointerless Pack now manufactures once into a disposable stage and qualifies that exact receipt/physical output before publication instead of running a redundant dry manufacture first. Routed Pack retains the necessary Core topology/allocation pass, consumes Core's exact route selector, then performs one exact physical manufacture; the redundant route-selected dry manufacture was removed.
- Benchmark — endpoint catalog: the same five-Workspace endpoint projection fell from about 11.3 seconds on the preceding host path to about 4.3 seconds after bounded parallel projection.
- Benchmark — participant projection: the same five-Workspace participant path fell from about 6.1 seconds to about 4.3 seconds.
- Benchmark — pointerless full build: the same five-Workspace package operation fell from about 17.1 seconds before the final manufacture de-duplication to about 7.8 seconds.
- Benchmark — routed full build: the same five-Workspace routed package operation fell from about 25.4 seconds to about 19.9 seconds while preserving the topology pass, final exact physical manufacture, route presentation and publication qualification.
- Bridge qualification: 121/121 VS Code bridge cases pass in the disposable exact-Core harness after the correctness and performance corrections.
- Package qualification: 6/6 package-integration scenarios pass, including displayed pointerless filename, exact Workspace reorientation, embedded current-Core bootstrap startup, routed multi-route Pack with physical Handoff/participant pointers, idempotent/non-overwriting publication and extracted VSIX execution of its bundled public Core entrypoint.
- Core preservation: no Core source file was modified by this work.

### Canonical Minimum Classification

- CM1 — current/attention-bearing contract minimum failures:
  - Missing required portable-contract headings, fields, sections, task fields, and interpretation fields are repair candidates only when the affected artifact is current, attention-bearing, generated for current consumption, or otherwise explicitly selected by its owner.
  - The recursive error families remain valid evidence of contract-shape debt, but error count alone does not authorize historical in-place migration.
  - Canonical minimum means the schema-required envelope, required ordinary sections/fields, and qualified integrity/footer representation for the artifact's governing schema version; optional prose or richer explanatory sections are not defects merely because they exceed the minimum.

- CM2 — Parent representation failures:
  - The 17 malformed Workspace-qualified recovery locators and the isolated missing Parent Origin are actionable representation defects because they can prevent deterministic recovery or misstate lineage.
  - Parent semantics belong in qualified Parent metadata/addressing and exact historical identity, not in directory shape, filename proximity, or same-path current bytes.
  - Core Major 010's fail-visible behavior is canonical: unavailable exact historical Parent bytes remain unavailable/missing rather than being silently rebound to current same-path material.

- CM3 — integrity qualification:
  - The 13 unqualified integrity-method references are canonical-form repair candidates where the artifact is authoritative/current.
  - The 14 missing-integrity warnings require schema- and role-aware review; absence is not automatically an error when the governing contract does not require integrity or the material is fixture/supporting content.
  - The 8 c14n-v2 mismatches are blockers only for authoritative artifacts whose declared integrity is expected to qualify. Fixtures/test vectors must be classified before any rewrite, because a deliberate mismatch may be test evidence rather than corrupted source.

- CM4 — immutable schema locator quality:
  - All 552 `schema.reference.exact-target-omitted` findings remain historical quality debt as classified by shared Tooling. They are not a project-wide rewrite queue.
  - Canonical forward behavior is to emit exact immutable schema targets when the applicable authoring contract requires them; historical migration requires separate explicit migration authority.
  - The 215 schema-authority-unavailable, 139 fallback-used, and 139 validator-unavailable warnings are qualification/environment signals, not proof that source semantics are invalid. They should be repaired in source only where a reproducible current authority/authoring defect is established.

### Topology Classification

- TP1 — numeric directories are semantically non-authoritative by themselves:
  - A numeric directory such as `001/` is not inherently invalid and must not be treated as a Parent, Major, continuation, ordering, or acceptance claim.
  - Numeric layout becomes harmful only when current tooling or human recovery depends on it to infer semantic lineage, when it conflicts with declared Parent/filename lineage, or when it creates ambiguous/stale discovery paths.

- TP2 — canonical lineage representation:
  - Artifact semantic lineage must be carried by the artifact's qualified Parent metadata and artifact identity/filename progression where the governing contract uses filename dimensions.
  - Directory nesting may organize repository material, but it must not substitute for or override declared Parent lineage.
  - Therefore the 26 extension-vscode numeric-directory paths are review debt, not a rename mandate. Any flatten/rename/reparent operation requires a separately authorized repository topology tranche with exact before/after lineage evidence.

- TP3 — Major versus continuation:
  - Carrier Major numbering, artifact filename progression, and directory numbering are separate dimensions unless an explicit qualified contract relates them.
  - A nested continuation-number directory must not be interpreted as a new semantic Major merely from path shape, and a Major directory must not be used to infer Parentage.

### Supporting Markdown Classification

- MD1 — supporting Markdown is allowed supporting material:
  - The 59 plain-Markdown surfaces are not invalid Tiinex leaves merely because they are outside Tiinex artifact schemas.
  - A Markdown file becomes shadow-documentation debt only when it duplicates a Tiinex-owned provenance, decision, authority, human-gate, current-state, or recovery responsibility and concrete semantic drift is established against the authoritative Tiinex artifact.
  - Cleanup disposition is therefore compare-first: retain when complementary/current, redirect when authoritative content moved, retire only when proven redundant/stale and repository ownership authorizes it.

### Current Versus Historical Disposition

- Current blockers / first-review candidates: current or attention-bearing portable minimum-form errors; malformed Parent representation; authoritative integrity mismatches; unqualified integrity-method references on current authoritative artifacts; missing integrity where the current governing schema requires it.
- Safe bounded repair candidates: current artifacts whose owner can repair required contract shape without changing semantics or historical identity; deterministic Parent locator repairs with exact intended target evidence; forward authoring defaults that prevent recurrence.
- Historical warning debt: the 552 exact-target omissions and other immutable historical representation quality findings unless separately selected for migration.
- Review-only debt: numeric-directory layout, supporting Markdown, authority-unavailable/fallback/validator-unavailable warnings, and integrity findings on fixtures/test vectors until their role is classified.

# Different viewers; the records should remain inspectable

As the artifacts accumulated, the developer tried several ways to see and operate on them: a VS Code extension and inspection tooling, a feedback-oriented public page, a feed-like Lineage Viewer and experiments in alternative visual presentations. A viewer is a **lens on source material**; it should not silently become the owner of its meaning.

## Source anchors that show the progression

- [Initial public Feedback Spine HTML, May 12](https://github.com/Tiinex/site/blob/9f842301b04de6932f4799536ad59982fe412054/index.html) — a real feedback/human-gate presentation surface before the Viewer.
- [June 19 Lineage Viewer orientation](https://github.com/Tiinex/site/blob/cc4acebf4a0603ca50bca2bbce375bb3e8d00f77/tiinex.app.llm.v1.md) — a separate source describing how the Viewer reads and displays portable Markdown artifacts.

The traceable-subagent experiment belongs to the earlier agent-review epoch; external GitHub issue Workspaces are separate later examples, not primary evidence for this chapter.

## A reader's question

If the same underlying source were presented as cards, a tree, a feed or a fantasy-world map, would its Parent, evidence and authority boundaries remain the same? That is the purpose of experimenting with presentations. A pleasing screen is not itself provenance.

## Evidence status

The GitHub pages and code establish that multiple artifacts and surfaces existed. The presenter's accounts establish the rationale behind some experiments. Neither implies cross-surface semantic parity has been universally verified.

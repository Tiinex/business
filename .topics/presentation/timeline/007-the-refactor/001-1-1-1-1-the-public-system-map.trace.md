# A public map of separated responsibilities

By **10 September 2026**, the project had enough named parts that explaining **where responsibility belonged** became an additional task. The Tiinex GitHub organization profile replaced an older roadmap image with a more explicit system map.

The map distinguishes business/human gates, canonical docs/schemas, shared mechanics in Core, sources and provider adapters, interoperability, applications, presentation surfaces, hosts and runtime/execution. At its center are **artifacts, Workspaces and Handoffs** rather than one application that owns all meaning.

- [Organization profile explaining that responsibility model](https://github.com/Tiinex/.github/blob/b645e3999b6de0b30784f9523efe87826a375765/profile/README.md) — accompanying descriptive text.

## How to read the image

This picture is **a map of intended component boundaries**, not a checkmark that every depicted repository was production-complete or had proven 1:1 schema/companion parity. The map's value is that it exposes the different responsibilities without implying a central platform must own the artifacts.

The image and its framing were revised more than once; this Topic pins one auditable September state rather than claiming to reconstruct every image-generation iteration.

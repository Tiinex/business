- Evidence Role: operator-identified behavioral deviation and bounded tool-path analysis, for owner-correct grounding verification; not a new universal Process or acceptance result.
- Review Context: Sigma's direct 2026-10-08 feedback after two isolated VS Code hotfixes were delivered as `.patch` files rather than a Tiinex-manufactured incoming Handoff Package.

## Evidence Material

- Material Kind: direct human correction, qualified process comparison and host-test status.
- Material: Sigma states that a workflow where an LLM routinely delivers Git patches and terminal commands violates the intended Tiinex artifact-first discipline, risks habituating roles away from durable Handoff Packages, and is a high-priority grounding risk. Sigma allows a loose `.patch` only for recovery where the VS Code extension is too broken to recover through Incoming Replace plus local build and reload.
- Current Governing Authority: [Anchor canonical holder role](../../roles/001-1-1-1-1-1-anchor-canonical-holder-cutover-role.trace.md) explicitly requires package-first normal recipient transfer. [Durable checkpoint discipline](../../processes/session-grounding-and-continuity/001-1-maintain-durable-checkpoint-package-discipline.trace.md) requires meaningful checkpoint packaging, distinct from fake recipient transfer, and exact human operator disposition. [ChatGPT canonical recipient transport](interop-openai::.topics/.processes/chatgpt-session-continuity/001-2-1-1-1-deliver-canonical-package-at-recipient-boundaries.trace.md) expressly disallows loose patches as equivalent to a Handoff Package.
- Actual Drift: two local repair candidates were emitted as detached Git patch files plus manual terminal instructions. The first Incoming Replace fix was reported successful on Windows. A later silent Windows Evidence Create recording still failed with `portable.operator-context.workspace-id.ambiguous`; its repair candidate has isolated checks but not Windows acceptance.
- Root Cause Classification: this is an execution/grounding adherence gap against already available qualified guidance, not evidence that a new broad Role, Process or Core semantic contract is required. The next transfer must use qualified Tiinex manufacture and exact selected Handoff pointer. A standalone patch is emergency/degraded recovery only when Incoming Replace plus build/reload is unavailable.
- Smallest Guardrail: before any recipient-facing source fix transport, require an explicit `transport disposition`: full qualified Workspace replacement carrier with formal Handoff/pointer for a real transfer; pointerless checkpoint only when no recipient transfer exists; `.patch` exception only with observed host path failure and explicit recovery reason. Confirm the actual delivered package and cold route, rather than trusting a chat promise.

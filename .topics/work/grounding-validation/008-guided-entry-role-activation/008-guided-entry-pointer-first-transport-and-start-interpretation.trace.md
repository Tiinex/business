- Supported Claim Or Question: Can a Guided Entry carry only selected Entry, Target and ordered Role pointers while the carrier's qualified Start owns receiver interpretation, preserving bounded explicit-session/operator participation and first-response verification?

## Evidence Material

**Observed problem:** The previous generated Guided Entry user message repeated a first-response verification paragraph, Entry/Target interpretation, long Primary Session Role and explicit operator-participant authorization prose. Although qualified Source/Start materials existed, the transport itself was effectively a second instructions document rather than a compact selection request.

**Change:** Existing Core `workspaceEntryProjection.js` now emits ordered selections with exact qualified pointers, including Primary Session Role and operator vs contextual participants. Existing Core `handoffPackageV1.render.js` now embeds the corresponding `Guided Entry Selection Interpretation` in the readable Start artifact. Start explicitly requires bootstrap/orientation before first response claims, qualifies Entry, Target and Role materials, enforces assignment modes and non-authority inference, and delegates host-facing speaker preferences to the carried Target.

**Directed tests:** The existing `workspace-entry-projection.test.mjs` and `transport-completion.test.mjs`, executed with Core's required runtime-content test bootstrap, passed 27/27. Coverage includes Start interpretation presence, compact role list, authorized vs unauthorized primary/operator roles, context-only participants, routed vs pointerless boundary and transport completion compatibility.

**Manual package and receiver test:** Standard Core manufacture with exact source roots and parent carrier yielded a full pointerless successor with roundtrip passing, 18/18 Workspaces. A separately extracted bootstrap from the manufactured carrier oriented all 18 Workspaces with zero findings, and its `project-transport-completion` produced a qualified Explore + ChatGPT Web + Anchor + operator Sigma selection. With exactly the same selections, transport shrank from 3,445 to 1,003 characters (70.9 percent reduction); formatting revision after this comparison only changed ordered index handling.

**Expected receiver behavior:** At first contact the LLM reads Start and follows its Tooling orientation before claiming readiness. It then interprets the brief transport as selections, qualifies Role Assignment Modes and behaves as Anchor with Sigma as operator-participant when authorized. Non-operator participants remain contextual. No Handoff, permanent holder, acceptance, Project/Task, Process, or remote-mutation authority is fabricated. Communication is concise and directed to the actual qualified participant.

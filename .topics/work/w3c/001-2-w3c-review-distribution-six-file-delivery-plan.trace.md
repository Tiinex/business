# Prepare the six-file W3C review and first-use distribution

**Disposition: planned and blocked.** This is a bounded expansion of the existing optional W3C presentation review Task, not authorization to publish, to represent W3C, or to assign a reviewer Role. The maintainer self-review already belongs to the original Task and remains a separate accepted feedback record.

## Objective

Once Guided Entry is independently accepted, prepare one human-facing outer distribution ZIP that lets external W3C-group readers inspect exact Tiinex presentation lineage, voluntarily review it through a real bounded Handoff, or start their own fresh Tiinex interaction. Use only established Tiinex carrier and Workspace semantics; the outer ZIP/README are presentation transport, not a new Tiinex artifact contract.

## Required distribution contents

Produce **exactly these six top-level files** in the human-facing distribution archive, after all individual qualification gates pass:

1. `completed-tests.zip` — collected formal tests with their actual measured outcomes, evidence limits, and disclosure review. Its presence does not imply all tests passed or W3C certification.
2. `001-3-tiinex-presentation.workspace.zip` — a Viewer-compatible Workspace ZIP containing only the presentation/current review material and exact required Parent and schema closure. Independently verify that the existing PoC Viewer can consume it; its inability to read Handoff packages is not a reason to invent a second semantic representation.
3. `tiinex-presentation.handoff-package.zip` — a **formal** Tiinex Handoff containing exactly the selected bounded presentation Workspace. Ground the exact current presentation Task, its maintainer Feedback, the approved publication revision, recipient Role/holder rules and permitted voluntary feedback/return path. Glimmer remains only a candidate until its actual Role contract and recipient assignment are qualified.
4. `tiinex.handoff-package.zip` — full, unfiltered Tiinex multi-Workspace carrier with Guided Entry for exploration. Run an explicit confidential-content and external-disclosure review before release. Carry genuine lineage and original bytes; do not assume all 17 Workspaces are safe to disclose merely because a carrier qualifies.
5. `tiinex-empty.handoff-package.zip` — genuine fresh bootstrap-only Tiinex entry without pre-existing work, Workspace selection, Task, Handoff route or transferred authority. Preserve a supported and clearly explained path to initialize the user's own work; do not fabricate an empty Workspace or authority from the name.
6. `README.md` — concise human-first instructions for ChatGPT Web and PoC Viewer, exact supplied package Start/transport text where appropriate, the companion navigation video including known Viewer limitations, how to give and export attributable feedback, and GitHub Issues only if this feedback route is actually verified.

## Acceptance and sequencing

- First finish 020 Core/Docs/Native/Interop OpenAI qualification and get **independent cold-start Guided Entry behavioral evidence** for ordinary work, a meaningful revision and natural stopping point. A green CLI orientation alone is insufficient.
- Obtain maintainer approval and an exact immutable publication commit and per-artifact presentation permalink; local `approved-for-publication` is not remote publication. Target each external observation to the exact reviewed revision, without implying W3C endorsement.
- Verify the selected reviewer Role, actual handoff endpoint/return obligations, bounded one-Workspace closure, and the recipient's authority separate from the carrier's mere presence. No compulsory feedback, affiliation, membership, or remote mutation is conferred.
- Verify the reduced Viewer representation preserves necessary Parent closure and that the Viewer works in practice despite known bugs. Test ChatGPT cold reception of each Handoff separately. A general full recovery must not silently substitute for a narrow reviewer Handoff.
- Inspect `completed-tests.zip` actual membership and outcomes, the full multi-Workspace package for disclosure/privacy, and the external README/video/feedback export instructions before release.
- Collect recipient words as their own observations. Distinguish human feedback from model interpretation and independent verification, and do not mark proposals accepted or implemented without the authorized human decision.
- Deliver the six-file outer ZIP only after these gates. Do not distribute provisional snapshots as official W3C feedback material.

## Done Criteria

- One outer ZIP contains precisely the six specified files, each with accurate provenance, safe disclosure and independently tested purpose-specific reception.
- The bounded formal presentation Handoff and the Viewer-compatible Workspace ZIP preserve the exact necessary Parent/Role/Task/Feedback context without exposing unrelated Business material.
- The full Guided Entry and fresh-empty carriers pass technical recovery and independent ordinary-language first-use acceptance, without invented authority.
- Review recipients have a tested voluntary method to provide feedback in ordinary words or qualified returned evidence; every report carries the actual revision target and authorship/verification distinctions.
- All unresolved dependencies below are closed by real published source, verified tests and human approval before external distribution. Until then this Task stays blocked.

## Scope

In scope: six user-specified distribution files, bounded W3C review authority and feedback paths, safe source selection, actual viewer/LLM testing, and a human-readable README/video. Out of scope: automatic W3C affiliation, changing canonical Tiinex rules, bypassing older Parent lineage, silently renaming canonical Core outputs, assigning a Role from carriage or publishing without approval.

## Dependencies

- Independently accepted Getting Started/Guided Entry with completed 020 Core, Native, Docs and OpenAI Interop qualifications.
- Maintainer-approved and published presentation revision with exact pinned source locators.
- Actual Role recipient/assignment and formal Handoff route qualification for voluntary review.
- Verified PoC Viewer navigation/export, ChatGPT cold reception, complete external-disclosure review for full multi-Workspace and tests.
- Verified README/video and feedback return instructions, including GitHub Issues only if actually operational.

## Dependencies and limits

This is an internal implementation plan under the original Task and maintainer Feedback, with no new external acceptance or publication. The six output names are requested user-facing distribution labels, not overrides of any canonical Tiinex filename emitted by Core Tooling: preserve and verify the Core projections and record any naming/transport conflict before external packaging. No GitHub update, Role appointment, Viewer bug repair, or formal Handoff has been performed by writing this plan.

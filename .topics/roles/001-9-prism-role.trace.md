# Prism Role

## Party Identity

- Party Label: Prism
- Party Kind: role

## Party Boundary

- In Scope: bounded implementation, qualification and experience refinement of presentation Verses, especially `Tiinex/verse-playthings`, under an explicit Task/Handoff.
- Out Of Scope: canonical Tiinex semantics, shared App/Core/Site ownership, final human acceptance, release authority, remote mutation, or treating presentation as semantic truth.

## Role Or Capacity

- Capacity: Presentation Verse specialist
- Capacity Context: explicit bounded work on presentation/projection Verses, currently including Verse Playthings browser/runtime qualification, deterministic projection, interaction quality and Verse-local repair.
- Responsibility: preserve supplied semantic source truth, implement or repair the delegated presentation slice, qualify it against the exact carried host/source set, and return evidence, blockers and a normal Handoff to Anchor.

## Reference And Privacy Boundary

- Reference Safety: Prism may be referenced as a Role endpoint or capacity in Tasks, Handoffs, Evidence and related Tiinex artifacts; such a reference does not identify or prove a concrete holder.
- Disclosure Boundary: this artifact defines a reusable project role only and must not contain credentials, account identifiers, private holder state or hidden runtime-session material.

## Use With Other Schemas

- Usable As: reusable Role reference for bounded presentation Verse implementation and technical qualification Tasks/Handoffs.
- Must Reference Separately: controlling Task/Handoff scope, holder/participant relation when it matters, technical Evidence/Validation, Sigma human acceptance, release/remote-write authorization, and any shared semantic or host-boundary authority.

## Role Identity

- Role Label: Prism
- Role Kind: presentation projection and experience specialist
- Organization: Tiinex
- Project: Tiinex

## Role Boundary

- In Scope: work inside the explicitly delegated presentation Verse source boundary; qualify runtime/package/browser behavior; improve Verse-local presentation, interaction and deterministic projection; preserve multi-workspace and companion behavior without inventing semantic truth; prepare concise Sigma test instructions after technical readiness; return exact blockers where shared host capability is missing.
- Out Of Scope: changing canonical schemas or lineage meaning; privately redefining Workspace, Parent, Relation, companion or presentation semantics; mutating App/Core/Site/Docs merely to simplify a Verse; declaring Sigma acceptance; broad new feature expansion outside the active Carrier Major; publication, deployment or remote push without separate authority.
- Context: Prism is the project Role name. `Playthings` remains the Verse/repository name and must not be used as the Role identity. A presentation Verse may make Tiinex material spatial, animated, visual or playful, but source artifacts and qualified relations remain semantic authority.

## Authority And Responsibility Boundary

- May Do: modify the bounded local presentation Verse implementation workspace transferred by an explicit Handoff; add focused tests/fixtures; run local package/runtime/browser qualification; repair Verse-local defects; preserve or improve accessibility and interaction quality; produce technical Evidence and a normal return Handoff.
- Does Not Authorize: shared architecture ownership; canonical semantic changes; final product acceptance; remote mutation/release; silent scope expansion; weakening provenance, validation or fail-closed behavior; treating visuals or companions as proof of artifact meaning.
- Required Instrument: bounded Verse work should be controlled by an explicit Task and transferred through a Handoff that names Prism as the Role/capacity. Shared changes, remote mutation, release or scope expansion require their own authority.
- Delegation: Anchor may route bounded presentation Verse work to Prism when the controlling task is implementation-ready. This Role does not by itself create delegation or acceptance.
- Review Boundary: Prism owns Verse-local implementation quality and technical qualification for delegated work. Anchor reconciles shared blockers and carrier progression; Sigma retains human experience acceptance.

## Holder Relationship

- Holder State: assignable per explicit session, invocation or Handoff; no permanent holder asserted
- Possible Holder: a person, model, runtime or coding agent explicitly operating in the Prism capacity for one bounded Tiinex context under supplied controlling artifacts and authority

## Interpretation Limits

- Does Not Prove: that a particular person/model/runtime currently holds Prism; that technical PASS is Sigma acceptance; that a visualization is semantic truth; that a remote push/release is authorized; or that this Role owns App/Core/Site/Docs semantics.
- Must Not Be Treated As: the Playthings Verse itself, schema authority, general product manager, final acceptance role, universal architecture owner, remote-write credential, semantic inference engine, or permission to expand an active Carrier Major without explicit reconciliation.
- Supersession Note: use Prism for new presentation-Verse delegations. The earlier `Playthings` Role artifact remains historical evidence for already-issued Handoffs and is not rewritten.

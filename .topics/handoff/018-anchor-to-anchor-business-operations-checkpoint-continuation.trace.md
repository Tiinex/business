  - Boundary: Anchor coordinates across roles but does not absorb Axiom schema authority, Loom shared-Tooling implementation authority, or Sigma human observation/durability authority.

- current-checkpoint-source
  - Transfer Kind: work-and-responsibility
  - Description: the carried Business Workspace contains the current reconciled semantic source set, including Axiom's materialized Human Transport Decision/Handoff/validation, the restored current-public Business artifacts needed by this lineage, and the new Anchor/Sigma transport, runtime, Vision, Public Surfaces, and public-challenge artifacts.
  - Boundary: this local source does not prove Git publication. The human operator must inspect/apply the checkpoint and perform the actual commit/push. Existing repository binary evidence assets that were not part of the supplied Business Workspace carrier are not authorized for deletion merely because they are absent from the semantic Workspace archive.

- axiom-human-transport-semantics
  - Transfer Kind: work
  - Description: Anchor accepts Axiom's Human Transport And Receiver Contract semantic disposition as the current bounded target. Handoff keeps endpoint/transfer/completion authority; human participation is minimal/explicit; receiver/human-transport contracts are qualification/projection rather than duplicate authority; Practitioner baseline composition remains typed non-Parent specialization; explicit multi-human dialogue can use non-Parent participation relations when durable evidence matters.
  - Boundary: no Tooling implementation or publication has occurred merely because the Decision is carried here.

- human-transport-acceptance-boundary
  - Transfer Kind: responsibility
  - Description: a human is mechanical courier by default unless explicit bounded human dialogue is requested. Successful durable work normally returns a workspace-bearing package. Human status stays outside the copy surface. Receiver copy blocks contain only literal transport/ingress instructions; if necessary receiver context exists only in the copy block, transport qualification fails.
  - Boundary: a single standalone Markdown return remains valid as an exception for a genuine blocker/finding or another deliberately bounded result when normal material closure cannot truthfully be reached.

- tooling-implementation-route
  - Transfer Kind: work
  - Description: after the Business checkpoint is remotely qualified, prepare a bounded Anchor-to-Loom implementation Handoff carrying Axiom's accepted semantics plus Sigma's receiver-copy/material-closure feedback. Loom should implement shared Tooling/presentation/qualification behavior and tests rather than create a second semantic contract.
  - Boundary: do not route this as proof that Tooling is generally complete. Handoff packaging has only recently become useful enough for LLM work.

- runtime-efficiency-and-parallelism
  - Transfer Kind: work-and-responsibility
  - Description: parallelize independent repositories, non-overlapping workspaces, and read-only discovery to reduce idle time. Serialize or isolate work sharing one mutable semantic authority and reconcile semantically before merge. Preserve Sigma's latency hypotheses as hypotheses; measure phase cost before causal claims.
  - Boundary: throughput optimization is not authority to evade, disguise, suppress, or bypass host safety controls.

- public-challenge-closure
  - Transfer Kind: work
  - Description: the 1000 SEK public AI-lineage challenge requires a traceable closure after the 2026-09-01 deadline or other published closing condition. Use the new child Task under Public Trust, reproduce both current Tiinex/docs submissions against the same qualification process, then create a comparative Decision and preserve payout/result/credit evidence.
  - Boundary: do not pre-judge based on effort, AI use, or low competition; use published criteria and require a working proof before comparative strongest-proof ranking.

- vision-and-current-grounding
  - Transfer Kind: work
  - Description: create the Business Vision layer from current `.github`, Docs, Site/refactor, revalidated provenance/tooling surfaces, and classified historical evidence. Separate current identity, current implementation, active direction, historical signal, superseded assumptions, and unproven ambition.
  - Boundary: historical `ai`, `ai-vscode-tools`, old architecture images, and old Site/Docs material are evidence, not automatic current authority.

- public-surfaces-and-hygiene
  - Transfer Kind: work
  - Description: execute the dedicated Public Surfaces And Repository Hygiene epic after the current durability boundary: GitHub organization first-contact, tiinex.dev entry Workspace, repo entrypoints/current-vs-stale presentation, Architecture Vision refresh, filtered current/history discovery, and recoverability-gated working-set cleanup.
  - Boundary: Git history remains historical authority; do not rewrite old read-only history merely to make lineage cosmetically neat.

- viewer-shared-capability-route
  - Transfer Kind: responsibility
  - Description: the current Site refactor is already the refactored Viewer version and has progressed materially. Resume product integration when the relevant shared Tooling/runtime capabilities are ready; replace Viewer-specific mechanics with shared capability where practical while preserving the proven PoC navigation experience.
  - Boundary: no consumer becomes a second semantic authority because its interaction model differs.

- checkpoint-convention
  - Transfer Kind: responsibility
  - Description: treat a major carrier/checkpoint as a stable, commit/push-worthy recovery point, not sprint or semver numbering. Avoid indefinite `-1-1-1` tails once a stable checkpoint exists.

- Recovery Rule: if a cold Anchor cannot reconstruct the current frontier from this Handoff plus its Required Context and carried Workspace without asking the human transporter to summarize prior chat, treat continuity as incomplete and repair the durable artifacts rather than shifting reconstruction work to the human.

# Tooling Major 008 — Core/LLM Direct Package V1 Freeze

## Decision

- State: accepted
- Subject: bounded Core/LLM direct Handoff Package V1 contract and recipient/return path after Tooling Major 008 closure.
- Decision: freeze the currently qualified direct Handoff Package V1 architecture and LLM-consumer path as the downstream contract for the next VS Code integration phase. The frozen scope includes Package V1 root/bootstrap/Workspace/cache/pointer conventions, adapter-native cache identity, carrier prefix/numeric continuation rules, grounding/readiness projections, Process/Policy applicability separation, recipient one-pass continuation, prepare-return/preflight/author flow, mechanical return-endpoint authority locks, and canonical one-Handoff-Package return transport. Reopen this freeze only for concrete qualified defect evidence or an explicit superseding authority.

## Basis

- [Final Freeze Qualification Evidence](../initiatives/036-tooling-major-008-final-core-llm-package-v1-freeze-qualification-evidence.trace.md) records the independent fresh minimal-coldstart-005 run, actual 005-1 returned package, repaired adversarial closing matrix, post-repair happy-path return, 270/270 current Core tests/subtests, portable smoke, embedded bootstrap qualification, and retired Handoff Package V2 anti-drift 3/3.
- Multiple earlier full-Workspace behavioral replays exposed leading historical/test-lineage leakage; the accepted minimal cold-start family removed that confound and independently demonstrated grounding/return behavior from one minimal Workspace plus exact external cache authority.
- The final failure-oriented closing test found one genuine authority seam in prepared-return endpoint mutability; Core now fails closed on all six mechanical endpoint coordinates while preserving recipient authorship of substantive return semantics.
- No known correctness blocker remains in the bounded direct Package V1 recipient/return path after repair and rerun.
- The freeze is local source/contract disposition only. No remote commit, push, release, publication, or downstream integration completion is inferred.

## Consequences

- Core direct Package V1 and the embedded LLM recipient/return contract are treated as stable inputs for the next downstream VS Code work.
- VS Code may consume the frozen Core path, but must not create its own Package V1/V2 authority model, sidecar truth, mapping database, pseudo-Workspace identity, or host-private semantic fallback.
- No new Handoff Package V2 compatibility mechanism is reintroduced. `sha256-base64url-c14n-v2` trace integrity remains valid and unrelated to the retired Package V2 transport design.
- Existing Package V1 structure remains readable: Start, bootstrap, Workspace ZIP(s), optional bounded cache ZIP, exact qualified Process/Policy/participant/endpoint/Handoff pointers, and Package V1 root. No additional freeze artifact is serialized into recipient packages.
- Carrier prefix/dimension remains transport/recovery progression only; semantic Parent remains artifact authority.
- Exact adapter-native references remain source identity; cache path remains transport placement only.
- Machine qualification, material availability, applicability, active execution, ownership, completion, and human acceptance remain separate dimensions.
- Local work products remain inside the continued Workspace and external normal completion transport remains one canonical Handoff Package plus exact routing text.
- A later concrete defect may reopen only the affected frozen surface; unrelated Core semantics remain frozen unless the new evidence requires broader reconsideration.
- Remote repository commit/push and organizational rollout remain human-controlled operations outside this Decision.

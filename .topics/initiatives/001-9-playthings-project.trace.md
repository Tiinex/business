# Tiinex Playthings

## Project Identity

- Description: Tiinex Playthings is the durable initiative for projecting ordinary Tiinex artifacts, lineage, time, parties, relations, and qualified companion resources into an interactive spatial Verse.
- Boundary: Playthings owns Playthings-specific experience, world projection, graphics contracts, runtime, and presentation. It does not redefine canonical Tiinex artifact semantics, replace Core, or make Site repository structure semantic authority.

## Project Purpose And Scope

- Description: Develop Playthings as a standalone React-compatible package and Workspace that can integrate through Core/App contracts while remaining moddable through artifact-local and schema-default `.playthings.*.png` companions.
- Boundary: Runtime implementation proceeds only through accepted Playthings planning/qualification. Site is an external host/deployment concern and remains read-only from the Playthings development lane unless explicitly handed off.

## Parties And Resources

- Relevant Parties: Sigma for product intent and human acceptance; Anchor for planning, architecture, lineage, implementation coordination, and review; Refactor Anchor for Core/App consumer boundaries; future specialist roles when bounded work warrants them.
- Relevant Resources: The standalone Tiinex/playthings repository, qualified Core/App consumer contracts when delivered, current Docs schemas, Business initiative context, Playthings graphics/tooling lineage, and Site as a frozen/host reference where required.

## Coordination State

- Description: Active planning initiative. The standalone Playthings repository exists and current work is refining the runtime/experience plan before implementation authorization.
- Boundary: Repository bootstrap, graphics production, designer review, implementation, host integration, and rollout are separate evidence/decision gates; existence of this Project does not imply runtime completion.

## Milestones And Outcomes

- Description: Near-term milestones are a qualified experience/semantic/spatial/time plan, executable Core/App consumer boundary, standalone runtime foundation, accepted Root vertical slice, package/host integration readiness, and first scale-out.
- Boundary: Carrier lineage majors are transport/progress checkpoints and do not replace Project milestones, artifact Parent lineage, or acceptance evidence.

## Interpretation Limits

- Does Not Prove: that Playthings runtime is implemented, npm-published, integrated into Site, semantically authoritative, or production-ready.
- Must Not Be Treated As: a replacement for Tiinex Core/App/Site, a new world-schema system, or permission to invent hidden Playthings metadata.

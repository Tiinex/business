# Tiinex Core

## Project Identity

- Description: Tiinex Core is the Initiative that owns the coherent semantic model behind Tiinex artifacts: provenance, continuity, lineage, schemas, policies, relations, coordination contracts, and interpretation boundaries.
- Boundary: Core owns semantic meaning and contract coherence, not shared Tooling implementation, host integration, Viewer UX, or legal/business administration.

## Project Purpose And Scope

- Description: Make Tiinex semantics stable enough that humans, LLMs, Tooling, Viewer, and future integrations can interpret the same artifacts without hidden provider-specific meaning.
- Boundary: Core may span repositories. Repository location does not define semantic ownership; canonical authority and qualified permalinks do.

## Parties And Resources

- Relevant Parties: Axiom for schema and semantic reconciliation; Anchor for cross-role architecture and review; Sigma for human intent and bounded acceptance; Loom as a consuming implementation peer.
- Relevant Resources: Canonical Docs schema/policy material, historical Site semantic dogfood, qualified repository sources, Tooling findings, and Business coordination artifacts.

## Coordination State

- Description: Hold during Foundation Readiness. Core semantics are used as current authority, but no broad Core development lane is active.
- Boundary: Re-open Core work only when Business/Docs/Site work demonstrates a concrete semantic gap that existing schemas or relations cannot truthfully represent. Do not create Core work for symmetry or cleanup convenience.

## Milestones And Outcomes

- Description: Meaningful outcomes include coherent artifact/schema contracts, trustworthy lineage/provenance/publication semantics, cross-repository coordination semantics, and later a reusable Process model derived from real artifact behavior.
- Boundary: Implementation success in Tooling or Viewer does not by itself prove Core semantic closure.

## Interpretation Limits

- Does Not Prove: that every existing schema is current, complete, implemented, published, or mutually coherent
- Must Not Be Treated As: the Tooling codebase, Viewer product, schema dump, or universal authority outside explicit canonical material

# Repository frontiers and lineage stabilization — Turn 2

## Objective

Stabilize the post-extraction Tiinex repository boundaries so each repository has a truthful current Workspace frontier, reusable implementation is not duplicated, stale Site history no longer dominates current discovery, and later Anchors can delegate work per repository without recovering architecture from chat history.

## Done Criteria

- Business has one current Turn-2 work package connected to the existing Core, Tooling, Viewer and Playthings initiatives without reassigning their semantic authority.
- Docs first-contact material distinguishes canonical Docs authority, Core implementation, App Viewer/application layer, Site deployment and Playthings Verse; future CLI, Interop, Chrome and VS Code hosts are not called current until their supplied Workspaces are qualified.
- Site current HEAD contains only deployment-relevant current lineage plus an observable Reduction boundary; removed historical artifacts and migration evidence remain exactly recoverable from immutable source material and Git after landing.
- Core/App/Site package and host boundaries are checked for private cross-repository imports, copied implementation and stale ownership language.
- CLI, Interop and Chrome receive truthful Workspace/package frontiers from their actual current repositories, or are explicitly recorded as not-yet-established rather than fabricated.
- A full-source successor carrier preserves every current Workspace plus reduction recovery material and tells a future Refactor Anchor which fronts may be delegated independently. VS Code remains a later front unless explicitly pulled into this Turn by Sigma.

## Scope

This is Foundation/Refactor stabilization, not broad product feature development. Repository names do not confer semantic authority: Docs remains canonical schema/documentation authority; Business owns initiative and human gates; Core implements shared host-neutral mechanics; App owns reusable Viewer/application infrastructure; Site owns the official web deployment; Playthings remains separately owned by its Playthings Anchor. Do not mutate GitHub through a connector. Ask Sigma for any existing Workspace that is absent from the supplied carrier rather than reconstructing it from assumptions.

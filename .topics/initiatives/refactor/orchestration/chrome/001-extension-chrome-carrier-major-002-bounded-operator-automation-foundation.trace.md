# Extension Chrome Carrier Major 002 — Bounded Operator Automation Foundation

## Objective

Turn the current source-minimal Chrome host frontier into a small, policy-respecting operator aid that can measure real run latency and reduce repetitive Handoff retrieval friction without becoming semantic authority, an OpenAI-specific implementation fork, or an aggressive browser automation loop.

## Done Criteria

- Audit the current `extension-chrome` foundation and its historical Parent/recovery state before extending it; do not create new artifact-lineage debt from the known older cross-Workspace locator pattern.
- Define and implement the smallest viable `play → finish` benchmark surface that records observable start/end timing without claiming model-internal timing or hidden runtime state.
- Detect and present slow-run / safety-check / delayed-run states only from observable browser/runtime evidence; wording must distinguish observation from inference.
- Improve the bounded extension UX enough that run state, benchmark result and Handoff download state are understandable without exposing implementation noise.
- Add a conservative Handoff-package download helper using explicit operator intent or a bounded observable completion signal, exact package identity dedupe, cooldown/backoff and one-download-per-qualified-result behavior.
- Do not use tight polling, repeated synthetic clicking, bypasses, hidden endpoint scraping, service-control circumvention, or behavior designed to defeat platform safeguards/rate limits.
- Keep OpenAI-specific host behavior outside generic Tiinex semantics; if a provider-specific capability is needed, return the boundary to Anchor rather than embedding it as Tiinex truth.
- Return technical evidence, explicit blockers and a short Sigma browser test card. Human acceptance remains separate.

## Scope

`Tiinex/extension-chrome` host-local implementation, browser UX, observable timing and bounded operator automation. Read-only consultation of current App/Core/Interop/Runtime/Docs contracts is allowed. Shared semantic or provider-specific changes require explicit re-routing.

## Safety Invariants

- Browser convenience never creates Handoff, Workspace, Parent, acceptance or completion authority.
- Automation must be event/state bounded and rate-conservative; no high-frequency polling or click loops.
- Safety/slow-run presentation reports only what the host can observe.
- Secrets, account identifiers and private conversation payloads do not become durable Tiinex artifacts by default.
- Carrier Major 002 is independent from artifact filename dimensions.
- Known historical artifact Parent debt in the Chrome repository is not silently normalized; any new artifact authoring must use qualified current mechanics or stay in the controlling Business lineage until the shared Tooling repair is available.

## Dependencies

- Current extension-chrome Workspace from Anchor recovery.
- Current App/Core/Interop/Runtime/Docs Workspaces as read-only contract context.
- Core Loom Carrier Major 002 lineage-safety repair remains authoritative for shared cross-Workspace Parent mechanics.
- Sigma owns real browser observation and human acceptance.

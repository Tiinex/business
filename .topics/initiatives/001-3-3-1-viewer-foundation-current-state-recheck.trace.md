# Viewer Foundation Current-State Recheck

## Discovery Intent

- Intent: re-evaluate only the Foundation-relevant Viewer and human-navigation conclusions that materially changed since the parent Discovery, and determine whether another implementation tranche is justified before human comprehension acceptance.
- Starting Question: after the latest Tooling and grounding repairs, which navigation requirements are already mechanically supported, which historical assumptions are obsolete, and what still requires human evidence rather than more code?

## Discovery Field

- Field: carried Business current source plus the current carried Site source after Loom's package-parent, static-debt, and closure-order repairs.
- In Scope: Feed/Tree/Lineage separation, loaded Parent traversal, current-versus-historical presentation, degraded/mismatch visibility, multi-workspace navigation primitives, real Business Task-to-root traversal, focused/Foundation/integration qualification, and the smallest remaining human-navigation gate.
- Out Of Scope: Atlas implementation, new graph ontology, role inheritance, new Policy schema, broad Viewer redesign, public-release claims, dependency installation/network repair, isolated Business-repository cold-start acceptance, or external-repository mutation.
- Freshness Boundary: this recheck uses the post-Loom carried source in the active carrier progression after accepted Major 003; these local deltas are not remote publication evidence until the next Sigma major checkpoint is accepted, committed, pushed, and verified.

## Discovery Method

- Method: inspect current Viewer source and UI-shape contracts, execute the current UI-shape guard and known-scenario matrix, feed all current Business trace artifacts into the current loaded-workspace lineage resolver, select the active Human Navigation Task as a real traversal start, and separate machine-verifiable behavior from human-only comprehension judgments.
- Evidence Approach: treat current source plus passing deterministic guards as implementation evidence, current Business artifacts as real dogfood material, and prior PoC/human observations as product evidence only. Do not infer human comprehension merely because source code or tests exist.

## Discovery Boundaries

- Semantic Boundary: operational grounding is now composition through explicit owners/bindings rather than a generic base Role inheritance model; this recheck does not reopen role inheritance.
- Qualification Boundary: current focused/tooling and Foundation gates pass; integration passes independently. Strict closure is not claimed because the host cannot currently complete the dependency-bootstrap step: the required Vite package is not cached and online npm installation stalls on registry access.
- Historical Boundary: a reduced historical checkpoint may correctly appear as an exact declared parent target that is not loaded in current HEAD; this is not a reason for the Viewer to fabricate a local edge.
- Human Boundary: deterministic checks may prove visibility, distinction, traversal, and fail-closed states, but cannot prove that a non-expert human understands the experience without a real human pass.
- Expansion Boundary: absence of a named portfolio feature is not itself evidence that a new portfolio ontology or UI is required. Existing multi-workspace and artifact-lineage behavior should be dogfooded before new semantics or surface area is added.

## Discovery Outcome

- Outcome: partial Foundation closure with no new Viewer implementation tranche justified yet.
- Recovered Machine-Visible Navigation: Feed, Tree, and Lineage remain distinct current views; Lineage resolves declared Parent/Trace edges rather than hidden adjacency; current/historical review is explicit and historical state is read-only with a visible Return to latest action; local/source-backed/mixed workspace boundaries use text plus icons; degraded, unavailable, ambiguous, and mismatch lineage states are explicit rather than collapsed.
- Current Guards: the current React UI-shape guard passes and the known-scenario matrix passes. Current broader qualification also remains static inherited 0 / introduced 0, focused/tooling 4/4, Foundation 54/54, and integration 12/12.
- Real Business Dogfood: loading the current Business trace set into the current lineage model and selecting Human Navigation And Active Frontier Experience yields a complete four-node verified Parent path: Human Navigation Task -> Tiinex Viewer Project -> Initiatives -> Tiinex organization root. All three Parent edges on that path are integrity-verified and the terminal state is root reached.
- Current Business Graph Repair: the dogfood pass exposed one stale Parent-integrity declaration in Workflow Observation Reconciliation after its parent process changed. The child declaration was repaired and resealed rather than weakening Viewer mismatch detection. The full current Business graph then retains only one non-root warning: a reduction artifact points to an exact commit-pinned historical checkpoint no longer present in current HEAD, which the Viewer truthfully reports as target unavailable.
- Obsolete Parent-Discovery Assumptions: the prior sequence item proposing shared/base-role inheritance is superseded by the accepted composable operational-grounding result: Role capacity remains distinct, applicability is explicit, and no base Role inheritance or new Policy schema is required for the current Foundation path.
- Qualification Update: the parent Discovery's broad statement that the current Viewer lacks a green present-state baseline is no longer current. The focused, Foundation, static, and integration gates now pass on the carried source. Strict closure remains separately blocked at host dependency availability rather than at the repaired orchestration order.
- Human Frontier: machine evidence is now strong enough that the next Human Navigation action should be a bounded human comprehension pass, not another Loom feature round. That pass should test whether a non-expert can identify workspace context, current versus historical state, Feed/Tree/Lineage purpose, the active artifact's upward Parent path, and cross-workspace return/navigation without repository archaeology or LLM explanation.
- Atlas Disposition: Atlas remains later product direction. Nothing in this recheck justifies moving it ahead of the remaining human-comprehension and release/runtime gates.
- Next Artifacts: preserve the human comprehension result as Sigma feedback/acceptance evidence. Open a new Loom task only if that pass reveals a reproducible human-navigation defect whose correction belongs to Site rather than Business artifact organization or documentation.

## Interpretation Limits

- Limits: this recheck does not prove public/browser release readiness, strict closure PASS, dependency availability, universal usability, successful isolated Business-only cold start, complete portfolio comprehension, Atlas readiness, or that every historical PoC interaction has been recovered. It proves a bounded current machine-visible navigation baseline and narrows the remaining Foundation navigation gate to real human comprehension unless new evidence contradicts that result.

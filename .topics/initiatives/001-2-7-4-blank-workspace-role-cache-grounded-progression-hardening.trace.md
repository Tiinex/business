# Blank-Workspace Role-Cache Grounded Progression Hardening

## Objective

Close the remaining known grounding gaps required before Tiinex can claim reliable grounded progression from a handoff package whose selected Workspace is intentionally blank/minimal while qualified Role/cache material carries the exact bounded authority needed by a fresh recipient.

The hardening must preserve the current fail-closed model: cache/carriage makes material available, never applicable or authoritative by itself; Role pointers do not create semantic participation; process applicability must remain forward-selected by controlling authority; missing source/participant/process authority must remain unresolved with an exact blocker.

## Active Parallel Work

- Axiom / Docs owns the semantic contract for process discoverability and Role/cache authority in a blank/minimal Workspace recipient.
- Loom / Core owns package construction, cache ordering/materialization, grounding projection, source/provenance diagnostics and adversarial validation for blank Workspace + qualified cache/Role material.
- Anchor retains Business integration, cross-return reconciliation, recovery acceptance and the blind fresh-Role validation carrier.

## Required Validation Shape

The acceptance target is not a rich complete-repository successor. It is a fresh recipient receiving a qualified Handoff carrier where:

- the selected Workspace representation may contain no substantive repository/project source beyond the minimum Workspace contract;
- exact route-bounded dependency bytes may be carried in the package cache surface between the Workspace descriptor and Role pointer chain;
- recipient Role material is recoverable without making Role carriage semantic participation;
- any process authority needed by the task is forward discoverable from controlling authority/Required Context rather than reverse inventory search;
- unavailable sibling/repository material remains unavailable rather than silently reconstructed;
- the fresh Role can establish its bounded authority, unresolveds, next permitted action and return path without Sigma reconstruction or hidden chat context.

## Done Criteria

- Axiom returns a qualified semantic disposition for blank/minimal Workspace + Role/cache grounding, including exact process-discoverability and participant/source authority boundaries.
- Loom returns a qualified Core implementation/validation result proving the carrier ordering/materialization and grounding behavior with adversarial tests for blank/minimal Workspace + cache/Role material.
- Cache carriage is proven to be material/provenance only and cannot silently establish process applicability, participant relevance, holder identity or implementation-source authority.
- A fresh-role acceptance carrier can be manufactured from the reconciled result without requiring complete Business/Docs/Core repositories in the selected Workspace.
- A verified 16-Workspace Full Recovery exists before the acceptance carrier is used as the next Master-Anchor progression gate.

## Scope

Current Carrier Major 001 grounding-hardening front only. This Task does not close all Tiinex ergonomics, Site/Playthings product work, pointerless transport UI behavior, or unrelated repository implementation.

## Dependencies

- accepted thin-lineage Test 3 source-authority behavior;
- accepted holder-binding authorization gate;
- accepted machine-derived ordinary carrier allocation;
- accepted process-applicability semantic disposition;
- latest verified Master Full Recovery and secondary-Anchor production trial evidence.

## Boundaries

- No new canonical schema family merely to make cache grounding convenient.
- No reverse process/Role inventory discovery.
- No treating cache/package order, file presence or Role pointers as semantic authority.
- No Business mutation by specialist Roles.
- No opportunistic remote/connector recovery when qualified material is absent.

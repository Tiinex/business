# Playthings Runtime Productization Epic

## Current Read

This Topic is the Business coordination parent for the current standalone Playthings development frontier. It is intentionally Epic-shaped in organizational use while remaining an ordinary `tiinex.topic.v1` artifact because the carried canonical Docs surface has no dedicated Epic schema.

The active Playthings Workspace owns the detailed designer, runtime, graphics, and process lineages. Those repository-local artifacts may deepen independently while this Business Topic remains the concise cross-repository initiative frontier.

## Design Direction

- Finish high-confidence experience, semantic, companion, spatial, temporal, actor, world, and presentation design before implementation authorization.
- Build runtime only in the standalone Playthings Workspace.
- Consume qualified Core/App public contracts rather than Site internals.
- Treat Site host integration as a later explicit handoff/cutover boundary.
- Keep final Playthings companions PNG-only and avoid hidden Playthings world metadata or provisional Floor/Room schemas merely for rendering convenience.

## Next Artifacts

The Playthings development root in the standalone repository is the direct continuation target. Business receives new descendants only when a durable initiative-level milestone, decision, risk, or cross-repository coordination state warrants it.

## Interpretation Limits

Calling this Topic an Epic describes its Business planning role; it does not create a new `tiinex.epic.v1` schema or imply that every Tiinex project must use an Epic layer.

# Tiinex

## Project Identity

- Description: Umbrella Project for developing Tiinex as one coherent recoverable human/AI work system across organizational, semantic, operational, human-facing, and exploratory product outcomes.
- Boundary: This Project coordinates durable child Projects and their outcomes. It is not the Tiinex Organization itself, does not make Workspaces into Projects, and does not imply that every child Project or historical frontier is active.

## Project Purpose And Scope

- Description: Keep Tiinex development coherent while allowing Business, Core, Tooling, Viewer, Playthings, and future real Projects to own distinct outcome boundaries and to span whatever Workspaces their work actually requires.
- Boundary: Project structure follows purpose and outcomes rather than repository layout. Tasks and Task children remain the default execution decomposition; new Projects require an independently meaningful purpose/scope/outcome boundary.

## Parties And Resources

- Relevant Parties: Sigma for human intent and acceptance; Anchor and qualified specialist Roles for coordination, design, implementation, review, and handoff according to current Role authority.
- Relevant Resources: Tiinex Business organizational material, Work Lifecycle and specialized Processes, current Project/Task topology Decision, canonical semantic authority, Tooling/runtime, Viewer/host surfaces, and product Workspaces.

## Coordination State

- Description: This is the fresh current umbrella Project boundary established after Major 017 cleanup. Its immediate child Projects define durable directions without reactivating historical execution leaves. Concrete execution must still be spawned as qualified Project or Task work through Tiinex Work Lifecycle.
- Boundary: Existing pre-portfolio Projects `003 Native Schema Authority Extraction` and `004 Deterministic Lineage Maintenance` remain truthful current transition Projects and are not silently reparented merely to make the new portfolio visually tidy.

## Milestones And Outcomes

- Description: Maintain a coherent Tiinex system in which organizational intent, semantic contracts, portable operations, human-facing interpretation, and bounded product experiments can evolve without hidden project truth or repository-shaped taxonomy.
- Boundary: Child Project progress and repository implementation evidence remain authoritative for their own outcomes; this umbrella does not manufacture completion from aggregation.

## Interpretation Limits

- Does Not Prove: product completion, commercial readiness, semantic closure, Tooling completeness, Viewer readiness, Playthings readiness, or activity in any child Project.
- Must Not Be Treated As: the Tiinex Organization artifact, a Workspace catalog, a mandatory Parent for authority artifacts, or permission to create Projects as generic grouping folders.

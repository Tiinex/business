# Foundation Schema Read Companion Coverage

## Discovery Intent

- Intent: determine whether current active Business artifact families already satisfy the human-readable schema-companion Done criterion or whether a bounded Site implementation gap remains.
- Starting Question: when the real current Business source is read through the current Viewer companion registry, which artifact families are exact schema-owned reads and which are only Root fallback?

## Discovery Field

- Field: all current carried Business trace artifacts and the current carried Site schema-read companion registry.
- In Scope: schema identity, exact-companion versus Root-fallback read state, current Business artifact family usage, and the smallest Foundation-critical missing set.
- Out Of Scope: semantic schema changes, authoring contracts, generic schema generation, every Docs schema family, Atlas, styling redesign, Resource/financial product work, or claims that Root fallback is unreadable.
- Freshness Boundary: local post-Major-003 carried source; no remote publication claim until the next accepted and verified major landing.

## Discovery Method

- Method: parse each current Business trace artifact, project it through the current Site schemaReadPresentation owner, group results by declared Current Schema, and classify exact-companion versus Root-fallback coverage. Prioritize only families directly encountered in current Foundation orientation, role grounding, organizational navigation, and reduction history.
- Evidence Approach: Root fallback counts as readable degraded coverage, not exact schema-owned coverage. A missing exact companion is treated as implementation evidence only when the Business Done criterion requires the active family to be human-readable through its own schema companion.

## Discovery Boundaries

- Fallback Boundary: Root fallback is intentionally safe and keeps Markdown inspectable; this finding does not classify fallback as data loss or invalid artifact state.
- Foundation Boundary: the implementation tranche should cover only the smallest active orientation/provenance set needed now. Secondary Resource, Financial Instrument, Follow, Research, and Transition Definition families remain separately visible and are not silently included.
- Semantic Boundary: a companion presents existing declared meaning. It must not add fields, infer status, merge Parent with Origin/Relation, or become schema authority.
- Regression Boundary: new companions must not weaken fallback behavior for unknown schemas or alter current Task/Topic/Decision/Relation/Handoff/Feedback/Preservation/Discovery companions.

## Discovery Outcome

- Outcome: bounded Site implementation gap found.
- Current Exact Families: Task, Topic, Decision, Relation, Handoff, Feedback, Preservation, and Discovery current Business artifacts resolve to exact schema-owned companions.
- Foundation-Critical Missing Families: Party Role, Project, Party Organization, and Reduction current Business artifacts resolve through explicit Root fallback rather than exact schema-owned companions.
- Why These Four First: Role is required for participant grounding; Project is on the real Human Navigation Task-to-root path; Party Organization is the Tiinex root reached by that path; Reduction is the current-history boundary used after accepted major landing. These four therefore directly support current Foundation comprehension rather than optional breadth.
- Secondary Missing Families: Resource/Resource Need/Contribution, Financial Instrument, Discovery Follow/Research, and Transition Definition also currently use Root fallback. They remain observable debt but are not authorized by this discovery as part of the next bounded tranche.
- Required Site Result: add exact human-readable read companions for the four Foundation-critical families using existing schema-owned companion conventions, preserving current semantic truth and safe Root fallback for all other unknown/unimplemented families.
- Next Artifact: one bounded Anchor-to-Loom Site Handoff after the prior Tooling return has an explicit Anchor disposition.

## Interpretation Limits

- Limits: this discovery does not prove that users understand the new companions, that secondary fallback families never need companions, that Root fallback is defective, or that a generic companion-generation framework is warranted. Human comprehension remains a later Sigma gate after deterministic companion coverage and regression checks pass.

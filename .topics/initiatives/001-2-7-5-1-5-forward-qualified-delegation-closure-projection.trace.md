# Forward-Qualified Delegation Closure Projection

## Objective

Close the remaining qualified-delegation mechanics gap exposed by the fresh Anchor acceptance: existing Tiinex semantics already distinguish specialist capability/relevance, delegation authority, process applicability, repo-local Task/source authority and return/reconciliation, but normal `ground` currently exposes delegation readiness only when equivalent projection objects are injected mechanically rather than recovered from the exact qualified current-work chain.

Establish one bounded Core implementation tranche that resolves those already-authorized claims from exact forward-selected Role/Task/Handoff/Decision/Relation/source-authority material carried by the selected route. The result must make a correctly authored acceptance carrier mechanically `qualified-for-delegation-authoring` without hidden caller JSON, while preserving fail-closed behavior when any claim is absent.

## Done Criteria

- Normal package `ground` can recover the five delegation-readiness dimensions from exact qualified route/current-work authority: delegate/capability selection, delegation/process applicability, target placement authority, Task/source authority and return/reconciliation expectation.
- Every positive projection names the exact qualified source artifact identity and forward selector that established it.
- Existing Role, Task/Epic, Handoff, Decision, typed Relation, Workspace/source-authority and pointer/reference semantics remain the semantic owners; no new Delegation, Participant, Capability-Map, Process-Applicability or readiness schema is introduced.
- Core does not parse arbitrary prose, infer from Role/cache inventory, reverse-scan Relations, infer source permission from writability, or treat a Handoff endpoint as delegation authority.
- The normal CLI/package path does not require hidden operator-provided delegation JSON to make already-qualified artifact authority visible.
- The projection remains executor-neutral/human-first: a human can read the same controlling artifacts; Core only qualifies/proves the chain.
- A blank/minimal selected Workspace plus qualified route-bounded cache material can expose the forward-selected authority chain without carrying unrelated repositories.
- Removing any one required authority claim reproduces the corresponding exact fail-closed blocker; plain-chat/repository-search fallback remains forbidden.
- Core still does not choose the delegate, generate the specialist Task body/work plan, or infer acceptance/completion.
- Full Core suite, portable smoke and embedded bootstrap qualification remain green.
- Loom returns exact Evidence and one qualified Loom-to-Anchor Handoff for reconciliation.

## Scope

Qualified-delegation artifact-to-projection resolution and focused acceptance regressions only. No new semantic schema, no holder redesign, no Business mutation by Loom, no product/source implementation, no generic grounding-receipt/UI work and no unrelated refactor.

## Dependencies

- Axiom `Qualified Delegation Grounding Semantic Disposition`.
- Business `Qualified Delegation Grounding And Transport Discipline` and `Blank-Workspace Qualified Delegation Acceptance`.
- Canonical holder hard cutover and active Role migration.
- Existing Core delegation-readiness projection and blank/minimal Role-cache mechanics.
- Fresh Anchor 008 fail-closed evidence showing all five delegation predicates remained unestablished despite the selected Axiom-review requirement.

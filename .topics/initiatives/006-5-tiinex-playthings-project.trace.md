# Tiinex Playthings

## Project Identity

- Description: Project for the interactive spatial Playthings experience that projects ordinary Tiinex artifacts, lineage, time, parties, relations, and qualified companion resources into a playful Verse/runtime product.
- Boundary: Playthings owns Playthings-specific experience, spatial/world projection, graphics contracts, runtime, and product outcomes without redefining canonical Tiinex artifact semantics.

## Project Purpose And Scope

- Description: Develop Playthings as a coherent product direction that can span Verse, Native, App, Site, graphics/resource, and other Workspaces only where those contributions serve a real Playthings outcome.
- Boundary: Workspace layout does not define Playthings project decomposition. Child Projects require their own outcomes; ordinary implementation increments remain Tasks/subtasks.

## Parties And Resources

- Relevant Parties: Sigma for product intent/acceptance and qualified product, design, runtime, graphics, architecture, implementation, and review Roles as bounded work requires.
- Relevant Resources: Verse Playthings, Verse Native/Atlas where applicable, App/Core contracts, graphical companion resources, Site/host references, and canonical semantic material.

## Coordination State

- Description: Playthings is re-established as a durable product direction without reactivating historical execution leaves or claiming an active runtime implementation frontier.
- Boundary: New Playthings work must be explicitly resumed through Work Lifecycle and current Project/Task artifacts rather than inferred from historical accepted/local state.

## Milestones And Outcomes

- Description: A coherent spatial/time interpretation model, usable runtime foundation, deterministic graphics/resource contracts, moddable package boundaries, host integration readiness, and bounded playable vertical slices.
- Boundary: These outcomes are directional and do not claim current implementation, publication, deployment, or production readiness.

## Interpretation Limits

- Does Not Prove: runtime completion, package publication, host integration, semantic authority, or production readiness.
- Must Not Be Treated As: a replacement for Core/Tooling/Viewer, a repository grouping, or permission to invent hidden Playthings-only semantic metadata.

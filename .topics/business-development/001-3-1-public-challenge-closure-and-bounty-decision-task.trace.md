# Public Challenge Closure And Bounty Decision

## Objective

Close the published "build a traceable AI lineage schema and prove it works" challenge transparently after its 2026-09-01 deadline or other published closing condition, using the criteria participants actually received and preserving qualification, comparative judgment, payout, credit, and closure provenance.

## Done Criteria

- Preserve the original challenge/publication Origin, 1000 SEK commitment, closing condition, published judging criteria, AI-allowed boundary, and any published participant feedback relevant to fair interpretation.
- Revalidate every submitted candidate against the same current qualification procedure before final judging.
- Reproduce the claimed working proof/validator rather than treating a README or submission claim as independent evidence.
- Separate qualification from comparative ranking: a candidate must first demonstrate a working proof and compatible Tiinex lineage/schema use before "strongest proof" decides the bounty.
- Judge usefulness, clarity, lineage compatibility, and participant/third-party evidence using the published criteria rather than adding effort-hours or other retroactive criteria.
- Preserve per-submission evidence, the comparative Decision, payout/result, proof of payment/distribution when performed, and public closure/credit.
- Give both submitters the same opportunity to rebase/revalidate/currentize before the deadline when doing so remains consistent with the published challenge.

## Current Submission Set To Revalidate

- Tiinex/docs PR #1, Jorel97: bounty-transparency lineage schema plus a concrete artifact for the real challenge and a Python standard-library validator. Last observed strength: real challenge dogfood. Last observed weakness: proof is substantially self-referential and structural; independent reproduction/current Tooling usage still needs qualification.
- Tiinex/docs PR #3, auruminternum: generalized bounty schema plus synthetic trace and dependency-free Node validator. Last observed strength: explicit general settlement model. Last observed weakness: synthetic rather than real-challenge proof, lineage choices require semantic scrutiny, and mergeability/current compatibility must be freshly rechecked.
- These descriptions are pre-judging observations, not winner selection and not substitutes for deadline-time evidence.

## Fairness Boundary

- AI assistance was explicitly allowed; do not penalize it as an unpublished criterion.
- Low competition does not invalidate the bounty commitment when a qualifying strongest proof exists.
- Competition strength does not make a broken/non-working proof qualify.
- Do not penalize a submission merely because Tiinex evolved while the challenge remained open; qualify against the current target with a fair opportunity to update where appropriate.

## Scope

- Challenge qualification, evidence reproduction, fair comparison, final Decision, payout/result provenance, and closure communication.
- Do not change the published challenge rules retroactively or expand this task into a general bounty-platform redesign.
- Use current Tooling only where it helps reproduce evidence; the task does not require new Tooling implementation unless a separate bounded blocker is materialized.

## Dependencies

- [Public Trust, Contribution And Governance Surface](001-3-public-trust-contribution-governance-task.trace.md)
- Existing Business financing/bounty lineage.
- Public Tiinex/docs challenge, PRs, comments, and reproducible submitted code at closure time.
- Sigma for final human payout/durability action; Anchor for evidence/reconciliation; Axiom only if schema-semantic ambiguity needs bounded review; Loom only if Tooling reproduction requires implementation expertise.

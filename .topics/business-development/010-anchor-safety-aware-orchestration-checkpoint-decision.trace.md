# Anchor Safety-Aware Orchestration Checkpoint

## Decision

- State: accepted
- Subject: current Anchor orchestration behavior before and after the first Git durability checkpoint
- Decision: the pre-commit Git quality gate remains accepted. Future Anchor continuations must additionally treat [Host Safety Review And Black-Box-First Operating Guidance](009-host-safety-review-black-box-first-operating-decision.trace.md) as current operating guidance. Use qualified Tiinex Tooling as a black box when it is sufficient, enter source/runtime inspection only when a concrete implementation or diagnosis need requires it, and preserve required safety and validation gates without classifier-evasion behavior.

## Orchestration Consequences

- This artifact is the current local Anchor orchestration leaf for the stabilization tranche.
- A cold-started successor Anchor should recover the portfolio from this lineage, then Discover the current Initiative/epic leaves rather than reconstructing the plan from host conversation memory.
- The Tooling efficiency epic now has a real child Decision containing the observed `1m 41s` black-box baseline, safety-review correlation evidence, cross-role operating rules, and performance experiment boundaries.
- Source/runtime inspection remains legitimate and required when a Tooling defect must be implemented or diagnosed. The optimization is to avoid unrelated or reassurance-only implementation archaeology, not to avoid safety review.
- Focused tests should precede broad suites during bounded iteration; integration/stabilization gates still own the broader qualification burden.
- After Sigma performs the accepted full-source Git durability checkpoint, Anchor must qualify the remote commits before launching parallel source mutation.
- After remote qualification, create a new Anchor orchestration child that records exact published commit/permalink recovery surfaces and the selected first-wave parallel Handoff routes.
- Minimal qualified Handoff closures are preferred for delegated work when sufficient; Anchor retains full-source Business/Docs/Site integration context for reconciliation and merge qualification.

## Evidence And Attribution

- Sigma supplied the timing concern, the stop/retry experiment, screenshots, and the observation that user-visible `Worked for` latency materially exceeded the apparent useful Tiinex runtime.
- Anchor reran the commit-gate work without the source/runtime inspection segment and observed a `Worked for 1m 41s` baseline while black-box Tooling operations themselves completed in sub-second to low-second ranges.
- The evidence supports an operating hypothesis that host-side additional safety review can dominate user-visible latency in some Tiinex turns. It does not prove the internal classifier trigger or attribute all long-running turns to one host mechanism.

## Review Conditions

- Reopen this guidance if measured evidence shows that the black-box-first practice reduces correctness, hides defects, or materially weakens qualification.
- Reopen the Git gate under the conditions already declared by the Parent Decision; this child does not relax those conditions.
- Preserve new latency/safety observations as first-class Sigma/human provenance when they materially change workflow design or performance conclusions.

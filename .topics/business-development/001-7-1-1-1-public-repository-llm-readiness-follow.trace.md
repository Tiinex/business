# Public Repository LLM Readiness Follow

## Follow Target

- Target: the public first-contact and bootstrap-readiness state of the Tiinex repository set governed by `Repository LLM Cold-Start And Bootstrap Surface`.
- Target Set: `Tiinex/.github`, `Tiinex/docs`, `Tiinex/site`, `Tiinex/ai-provenance`, `Tiinex/ai`, `Tiinex/ai-vscode-tools`, and `Tiinex/business`.

## Follow Basis

- Basis: foundation readiness requires a blank public reader or LLM to recover correct Tiinex identity and a safe next step without project archaeology.
- Basis Artifact: `Public Repository LLM Ingress Baseline` records the initial 2026-08-29 state.

## Interest Boundary

- Interested In: root first-contact files, explicit repository status/current-vs-history guidance, organization identity routing, bootstrap locator/ref/checksum/verification state, and cold-start acceptance outcomes.
- Not Interested In: unrelated code churn, general issue activity, user activity, private material, implementation details that do not change cold-start readiness, or broad repository crawling.
- Authority Boundary: observation does not upgrade a moving branch, README claim, or discovered file into release or semantic authority.

## Update Expectation

- Expectation: on-demand/manual resolution while Tooling/Viewer lack exact `tiinex.discovery.follow.v1` execution companions.
- Future Capability: when a qualified Discovery Follow resolver exists, it may refresh only the declared target set and boundaries instead of opening additional Business Workspaces.
- Desired Projection: show per-repository ready/degraded/blocked state with direct source evidence and preserve findings separately when a material change is discovered.

## Stop Or Review Condition

- Review: re-evaluate when repository ingress files change, the public bootstrap publication route changes, Site branch/release policy changes, or the foundation gate is reviewed.
- Stop: this follow may close when every in-scope public repository passes the agreed cold-reader acceptance test and Sigma accepts the foundation, or when a successor artifact explicitly replaces this target set.

## Interpretation Limits

- Following these repository surfaces does not prove model-provider behavior, release qualification, security, correctness of every repo claim, or permission to mutate any repository.
- A green discovery projection is not sufficient by itself to close the parent task; explicit cold-start acceptance/validation evidence remains required.
- Until exact Follow runtime support exists, refresh results are manual bounded observations and must disclose freshness.

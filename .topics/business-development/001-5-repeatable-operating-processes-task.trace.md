# Repeatable Operating Processes

## Objective

Derive reusable Tiinex operating Processes from repeated successful artifact behavior so multiple roles can follow the same method without duplicating procedures inside Role instructions.

## Done Criteria

- Process semantics are based on several real artifact sequences rather than an invented methodology.
- Definition, execution/run evidence, step references, deviation handling, and Parent-versus-process-membership semantics are explicitly resolved.
- Roles can reference reusable Processes while retaining their own authority boundaries.
- Human and LLM execution can use the same process facts without hidden parallel instructions.

## Scope

- This epic is intentionally later-phase and should not author Process artifacts before sufficient real evidence exists.
- Do not use Process as Parent merely to encode membership when Parent would cease to mean direct continuity.
- Deviations must remain visible rather than being normalized away.

## Dependencies

- Core Process semantic work package.
- Completed examples from Business, Tooling, Viewer, Handoff, and review workflows.

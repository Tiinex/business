# Anchor Business Stabilization And Parallel Workstreams Decision

## Decision

- State: accepted
- Subject: Business graph stabilization, new Tooling work packages, parallel execution readiness, and first Git quality gate
- Decision: Repair existing epic Tasks as direct children of their Business Development or Initiative Project when they are genuine decomposition; preserve typed non-parent association for work that is merely related. Supersede the temporary local Related Project fallback from the earlier portfolio Decision now that Axiom and Loom have qualified truthful relative Parent Origin. Add Tooling And Workflow Iteration Efficiency and Browser Companion And Bounded Human-In-The-Loop Transport as Tooling epics, with the separate accepted access-level Decision as their governing transport boundary. Do not create subtasks yet. After bounded Business/Docs/Site validation and Discovery review, Sigma may make the first semantic Git durability checkpoint; subsequent cleanup and broad parallel epic decomposition occur only after that checkpoint provides recoverable source history.

## Basis

- Axiom accepted local relative Parent Origin and Project-to-Task parentage for genuine direct decomposition.
- Loom returned runtime projection convergence so portable validation and authoring no longer need fabricated browse + git evidence for unpublished local Parents.
- The existing epic artifacts were created directly as decomposition of their Projects, so their previous root state was an authoring fallback rather than intended semantics.
- Observed 15–25 minute or longer multi-role wall-clock turns justify a dedicated efficiency epic, while the historical Chrome bridge idea plus current browser/CLI portability justify a separate browser companion epic.
- Parallel execution is valuable only when epic boundaries, dependencies, mutation surfaces, and integration gates remain explicit.

## Consequences

- New artifact authoring in this Business tranche is parentage-first: a root is created only when root semantics are actually intended.
- Existing Handoff/Decision/Research roots are repaired only where direct continuation evidence is clear; historical or independent roots are not cosmetically attached.
- The first post-stabilization Git checkpoint is semantic durability, not proof of remote publication, funding, roadmap completion, or cleanup closure.
- After the checkpoint, independent epics may be decomposed in parallel by bounded roles and then reconciled by Anchor before parallel implementation.
- Roadmap remains deferred until the stable epic landscape and meaningful milestone candidates are visible; reusable Processes remain last and evidence-derived.

## Review Conditions

- Block the Git quality gate if new validation errors arise from this stabilization work or if Discovery still shows accidental roots among the newly repaired/current artifacts.
- Known historical/transport residue must be explicitly classified rather than silently counted as current product work.
